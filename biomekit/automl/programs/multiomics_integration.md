# program.md - Multi-omics Integration for Phenotype Prediction

> **场景**: 多组学整合预测模型 (基因组+代谢组+表型)
> **适用**: 承葛医药微生态药物研发 + 多中心数据整合分析

---

## 🔬 研究目标

整合宏基因组 (物种/功能)、代谢组 (血清/粪便)、临床表型数据,
构建优于单组学的疾病风险预测或疗效评估模型。

**评价指标**: 多目标优化 - 性能(0.6) + 单组学增益(0.2) + 可解释性(0.2)

---

## 📊 数据规范

- 模态1: 宏基因组 - 物种丰度表 + KEGG通路丰度
- 模态2: 代谢组 - 靶向/非靶向代谢物丰度 (已标准化)
- 模态3: 临床 - 年龄, 性别, 用药, 疾病分期等
- 缺失处理: 允许部分样本缺失某模态, 需设计鲁棒融合策略
- 目标变量: 连续型 (如炎症评分) 或分类型 (如疾病亚型)

---

## 🧭 搜索空间 (核心探索点)

### 融合策略
- [x] 早期融合: 拼接所有特征 → 统一建模 (需处理量纲/稀疏性)
- [x] 晚期融合: 各组学单独建模 → 集成预测结果
- [x] 中间融合: 矩阵分解风格学习共享/特有因子

### 模态特异性处理
- [x] 基因组: 系统发育聚合 (在属/科水平聚合以减少稀疏性)
- [x] 代谢组: 处理检测限问题, 稀疏性处理
- [x] 临床数据: 嵌入分类变量, 处理时间动态 (若有时序)

### 正则化与可解释性
- [x] 组稀疏: 鼓励同一通路/模块的特征共同入选
- [x] 因果约束: 若先验知识表明"菌→代谢物→表型", 可加入结构约束

### 模型策略
- [x] `rf` - RandomForest (基线模型)
- [x] `xgb` - XGBoost (高精度需求)
- [x] `lr` - 正则化逻辑回归 (可解释性)
- [x] `mlp` - MLP (非线性融合)

---

## 📏 评估函数

### 主指标
- 5折嵌套交叉验证的测试集性能 (ROC-AUC 或 F1-macro)

### 增益指标
- 多组学相比最佳单组学的性能提升 Δ ≥ 0.05 (效应量门槛)
- 跨队列泛化: 在独立外部数据集上的性能衰减 ≤ 15%

### 可解释性评分
- 是否识别出已知生物学通路 (如"丁酸合成→抗炎")
- 特征重要性是否与文献一致

### 综合得分
```
score = 0.6×Performance + 0.2×Δ_SingleOmics + 0.2×Interpretability
```

---

## 🧬 领域约束规则

1. **[必须]** 融合过程需保留"模态可追溯性": 能回溯预测结果依赖哪些组学的哪些特征
2. **[必须]** 处理批次效应: 若数据来自多中心, 需在prepare.py中集成校正
3. **[禁止]** 使用未来信息: 如用移植后代谢组预测移植前表型
4. **[建议]** 优先选择"机制可假设"的关联: "菌A富集→代谢物B升高→表型C改善"

---

## 🔄 迭代策略

- 第一阶段 (1-20次): 探索单模态基线, 确定各组学单独的最佳建模方式
- 第二阶段 (21-50次): 聚焦融合策略, 比较不同整合方法的增益
- 第三阶段 (51+次): 优化可解释性, 在性能持平前提下选择更"生物学合理"的方案

---

## 📤 输出规范

- `integration_architecture`: 融合流程图 + 关键代码
- `cross_modal_insights`: 发现的"菌-代谢物-表型"三联体假设
- `failure_analysis`: 哪些样本预测不准? 是否与特定亚群/批次相关?
- `deployment_note`: 模型推理时所需的最小数据模态组合

## 🚫 终止条件

- 达到性能门槛 + 外部验证通过
- 或 识别出3+个有潜力的生物学新假设 (供湿实验验证)
- 或 业务方确认方案可进入产品化开发
